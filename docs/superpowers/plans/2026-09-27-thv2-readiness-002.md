## Goal
Harden the existing Trick Harness architecture so a real engineering workflow can survive provider/runtime failures, process restarts and ambiguous external side effects while remaining observable, fail-closed and deterministic.
## Architecture
Keep the current Trick Harness TypeScript core. Add durable progress projection, a deterministic recovery-policy layer, explicit restart/checkpoint semantics, side-effect idempotency/world reconciliation, workspace leasing and a provider-neutral failure taxonomy.
Temporal, LangGraph, OpenHands and OpenAI Agents SDK are architectural references only. No new orchestration framework dependency is added by this Plan.

## Review focus
1. **Crash between side-effect request and confirmation** — restart must verify world state, not duplicate delivery.
2. **Partial mutation before executor failure** — retry must reconcile workspace first.
3. **Constraint that is recoverable but non-PASS** — recovery may continue, but no stale/constrainted reading may certify the branch.
4. **Runtime upgrade with old durable journal** — explicit compatible read or bounded incompatibility refusal.
5. **Concurrent workflows** — same writable workspace must serialize/refuse while isolated workspaces can progress independently.

## Task 2 — Deterministic recovery-policy engine
**Owner:** Trick Harness
**Files:**
- Create: `packages/core/engineering-workflow/src/recovery-policy.ts`
- Modify: `packages/core/engineering-workflow/src/index.ts`
- Modify: `packages/core/engineering-workflow/src/triage.ts`
- Modify: `packages/core/engineering-workflow/src/types.ts`

- Test: `packages/core/engineering-workflow/tests/workflow.spec.ts`
- Create/Test: `packages/core/engineering-workflow/tests/recovery-policy.spec.ts`
**Interfaces:**
Define a deterministic pure function equivalent to:
`decideRecovery(input: RecoveryContext): RecoveryDecision`
`RecoveryDecision` must be a discriminated union. Allowed dispositions:
- `RETRY_SAME_EXECUTOR`
- `REROUTE_EXECUTOR`
- `REPROVISION_WORKSPACE`
- `RECONCILE_WORKSPACE`
- `RECONCILE_WORLD_STATE`
- `VERIFY_RECOVERED_MUTATION`
- `PAUSE_FOR_HUMAN`
- `TERMINAL_BLOCKED`
- `TERMINAL_INCONCLUSIVE`
- `TERMINAL_FAIL`
Each variant carries only the fields valid for that disposition plus a bounded machine-readable `reasonCode`. Contradictory combinations such as `TERMINAL_FAIL + retryAllowed=true` must be impossible by construction.
`VERIFY_RECOVERED_MUTATION` is a RecoveryDecision variant, not an out-of-band transition. Its required payload is `reasonCode`, `sourceAttemptId`, `checkpointId`, `reconciliationId`, `evidenceAnchorId`, and `verificationStageId`, all bounded identifiers. The target must be the independent read-only verification stage identified by the recorded execution plan. Journal this decision before dispatch. Only the fresh verifier can establish verification PASS; the interrupted implement attempt stays non-PASS. No compatible independent verifier means PAUSE_FOR_HUMAN. The variant is forbidden for ambiguous repair and whenever writer quiescence, workspace attribution, scope or evidence anchors remain unproven.
Keep two independent concepts:
- **Stage assurance:** `PASS | FAIL | PARTIAL | BLOCKED | INCONCLUSIVE`.
- **Workflow recovery:** retry, reroute, reprovision, reconcile, pause, or terminate.
A stage may remain `INCONCLUSIVE` while the workflow deterministically chooses a safe recovery path and later obtains a fresh stage reading. Recovery never upgrades an uncertain reading to PASS.
`RecoveryContext` must include at minimum:
- `stageId`
- `role`
- `risk`
- `permissionMode`
- `attempt`
- `priorRecoveryAttempts`
- `priorRouteFailures`
- `executor`
- bounded failure fact when present
- `constraints`
- workspace-state summary
- external-side-effect state
- `independenceRequirement`
- compatible available executors
- profile-derived recovery budgets
**Constraint defaults:**
- `EXTERNAL_SERVICE_UNAVAILABLE` → bounded retry; then reroute when policy permits; otherwise human/terminal.
- `EXECUTOR_CAPABILITY_GAP` → reroute to a compatible executor; never blind same-executor retry.
- `SANDBOX_LIMITATION` → reprovision workspace/environment when reconstructible; otherwise human.
- `MISSING_TOOL` → reprovision when the tool is part of the declared environment contract; otherwise human.
- `EXTERNAL_RUNTIME_UNREADABLE` → bounded retry/reprovision according to the affected boundary; persistent inability becomes human/inconclusive.
**Precedence:**
`workspace/world uncertainty > human decision > reprovision > reroute > retry > terminal evaluation`.
If prior mutation or external side-effect outcome is ambiguous, no ordinary retry/reroute is allowed first. The decision must be `RECONCILE_WORKSPACE` or `RECONCILE_WORLD_STATE`.
**Unknown failure rule:**
`unknown` is not availability. A failure may be automatically retried or rerouted only when deterministic bounded evidence classifies it into a recovery-enabled failure class. An unknown failure defaults to human/terminal inconclusive according to policy.
**Mutation rule:**
For `implement` and `repair`, any failure after `workspace-write` authority has been granted cannot directly result in `RETRY_SAME_EXECUTOR`. The recovery engine must require `RECONCILE_WORKSPACE`; Task 3 owns the reconciliation mechanism.
**Durability:**
Every recovery decision must be journaled as a durable event containing the stage/attempt identity, disposition and bounded reason code, so restart can reconstruct not only what failed but why the control plane chose the next transition.
**Frozen recovery policy:** At admission resolve a versioned `RecoveryBudgetPolicy` from the selected profile, validate it, and persist its full bounded numeric values plus SHA-256 in the immutable execution-plan record. Required values are `attemptDeadlineMsByRole`, `maxSameExecutorRetriesPerStage`, `maxReroutesPerStage`, `maxReprovisionsPerStage`, `maxReconciliationsPerStage`, `maxRecoveryTransitionsPerWorkflow`, `recoveryDeadlineMs`, `backoffInitialMs`, `backoffMultiplier`, `backoffMaxMs`, and `quiescenceDeadlineMs`. Counts are nonnegative integers; durations are finite positive integers; multiplier is finite and at least 1. No implicit infinite budget or provider-selected default is allowed. Missing/invalid values refuse admission with POLICY_CONFIGURATION_INVALID. Use the existing reviewed profile values when present; any new profile must explicitly supply all values before execution. Do not invent production values from test fixtures.
Backoff for retry index n (starting at 1) is min(backoffMaxMs, backoffInitialMs \* backoffMultiplier\^(n-1)), without hidden jitter. Persist consumed counters, absolute recovery deadline and next eligible retry time before dispatch. Resume preserves consumed budgets and deadlines; restarting, rerouting or pausing cannot reset them. Clock ambiguity fails closed. A test profile with deadline 1000 ms, two retries and backoff 100/200 ms must prove that restart after retry 1 permits only retry 2; separate zero-budget and workflow-total-cap cases prove termination.

- [ ] **Step 2:** Write tests for transient availability, capability mismatch, auth/configuration, unknown failure, artifact defect and human-only decision.
- [ ] **Step 3:** Add type/runtime tests proving invalid/contradictory RecoveryDecision shapes cannot be emitted.
- [ ] **Step 3a:** Verify the recovered-mutation variant round-trips through journal/status/resume, dispatches exactly one fresh independent read-only verifier, never upgrades the original attempt, and rejects ambiguous repair or missing quiescence.
- [ ] **Step 3b:** Test policy validation, exact backoff values, persisted counters/deadlines, zero budget, total transition cap and restart without budget reset.
- [ ] **Step 4:** Prove that `constraints.length > 0` still prevents PASS but no longer automatically determines whole-workflow termination.
- [ ] **Step 5:** Add precedence tests proving ambiguous workspace/world state outranks retry/reroute.
- [ ] **Step 6:** Add recovery-budget tests preventing unbounded retry/reroute loops.
- [ ] **Step 7:** Implement recovery policy as pure deterministic code.

**Done when:** operational recovery is a typed, durable control-plane decision rather than a model decision, boolean combination, or generic `INCONCLUSIVE` shortcut.

**Interfaces:**
Every mutation-capable attempt must have a durable pre-attempt workspace checkpoint created and flushed **before** the executor receives `workspace-write`.
Required ordering:
`capture checkpoint → persist checkpoint → durable flush → record checkpoint identity → executor-start/workspace-write`.
If the checkpoint cannot be durably established, the mutation-capable attempt must not start.
The checkpoint must distinguish repository revision, index/staged state, worktree state, untracked state and the bounded path-state fingerprints required for later attribution. Do not persist file contents.
A durable journal event stores at minimum:
- `checkpointId`
- `workflowId`
- `stageId`
- `attemptId`
- immutable revision
- entry count
- checkpoint SHA-256 / content identity
- timestamp or durable sequence identity
The complete bounded path-state checkpoint may live in the durable session/checkpoint store referenced by that journal identity.
**Workspace reconciliation result:**
- `NO_MUTATION`
- `IN_SCOPE_MUTATION`
- `OUT_OF_SCOPE_MUTATION`
- `PREEXISTING_USER_STATE_TOUCHED`
- `REVISION_MOVED`
- `SNAPSHOT_UNREADABLE`
- `UNOBSERVABLE_MUTATION_SURFACE`
Reconciliation is **read-only**. It establishes what happened; it does not clean, reset, restore, checkout, revert, stage or otherwise mutate the workspace.
Reconciliation used to authorize continuation requires the writer-quiescence barrier defined in Task 4. A lease acquisition, AbortSignal, timeout, absent PID or stable-looking snapshot alone is not proof that the previous writer has stopped. Without proven quiescence, status may be inspected but no conclusive reconciliation or replacement writer may proceed.
The runtime must separately model:
- Git index/staged state;
- worktree bytes/state;
- untracked paths;
- pre-existing user-owned dirty state.
A path already dirty before the attempt remains user-owned state. The Harness must never automatically roll it back or overwrite it merely because the same path is inside the approved Plan.
Ignored/writable surfaces require an explicit observability guarantee. Either the sandbox prevents unauthorized writes there, or the workspace reader deterministically covers every ignored/protected writable surface relevant to the attempt. If neither is provable, reconciliation returns `UNOBSERVABLE_MUTATION_SURFACE`.
**Recovered implementation mutation:**
If an `implement` attempt ends `INCONCLUSIVE` or operationally fails after writing, but reconciliation proves all observed mutation is deterministic, in-scope, the revision is stable, no pre-existing user state was touched and no unobservable writable surface exists, the original attempt remains non-PASS.
The recovery engine may then emit `VERIFY_RECOVERED_MUTATION`, causing a fresh independent read-only verification of the preserved workspace state rather than re-running implementation or synthesizing PASS.
For `repair`, do not synthesize missing repair evidence. An ambiguous repair result remains human/terminally gated until a separately specified recovery assessment can establish all repair-contract obligations.

- provider-neutral `category`;
- stable provider-specific `code`;
- bounded `failurePhase`;
- optional safe diagnostic metadata explicitly whitelisted by the adapter.
Minimum `failurePhase` values:
- `STARTUP`
- `SESSION_CREATE`
- `PROMPT`
- `SESSION_ABORT`
- `CLEANUP`
The core may branch on provider-neutral category and recovery policy. It must not import OpenCode SDK error classes or parse OpenCode-specific strings.
**Classification boundary:**
Introduce or isolate a pure compatibility function equivalent to:
`classifySdkFailure(error, context): ExecutorFailure`
It may use only stable, explicitly reviewed signals from the exact pinned SDK contract, such as known error discriminators/classes, structured HTTP status/code, the Harness-owned AbortSignal/deadline, and the operation phase.
Do not base recovery classification or persisted diagnostics on arbitrary `error.message`, response bodies, stack traces, raw provider output or unrestricted nested causes.
**Initial conservative mapping:**
- proven connection/request timeout → `transport-unavailable`;
- proven connection failure → `transport-unavailable`;
- proven 429/quota/usage condition → existing usage-limit category;
- proven provider overload/503 → `server-overloaded`;
- proven provider/server 5xx internal fault → `internal-server-error`;
- proven authentication/authorization failure → `unauthorized`;
- proven invalid request → `bad-request`;
- malformed SDK/provider response → `other` with stable malformed-response code;
- spontaneous session abort not initiated by the Harness → `other` unless stronger deterministic evidence exists;
- unknown/unclassified error → `other`.
**Unknown rule:**
`unknown` is not availability. An unknown failure remains non-retryable/non-reroutable unless another deterministic layer establishes a recovery-enabled class.
**Cancellation and deadline separation:**
Distinguish:
- caller/Harness cancellation — workflow control event, not provider outage;
- Harness attempt deadline expiry — bounded attempt timeout fed to recovery policy;
- provider/OpenCode spontaneous session abort — provider failure signal, conservatively classified.
Every OpenCode attempt, including `session.prompt()`, must be bounded by a Harness-owned attempt deadline propagated via AbortSignal or an equivalent deterministic mechanism. The provider does not choose the workflow's time budget.
**Retry ownership:**
**Writer-quiescence contract:** Define `ensureWriterQuiescence(attemptId, workspaceId, deadlineAt): Promise<WriterQuiescenceResult>` in `packages/core/engineering-workflow/src/types.ts`, implemented by the trusted host/provider boundary. The discriminated result is `QUIESCENT` with bounded evidence identity and proof kind (confirmed termination of all write-capable execution descendants, or enforceable revocation of their write authority), or `UNPROVEN` with a bounded reason code. Persist the result and its correlation to the interrupted attempt; on restart revalidate live authority before relying on it. A completed abort request is not confirmed termination.
On timeout/cancellation/lease loss, revoke further dispatch, terminate or fence existing writers, prove quiescence, and only then reconcile or launch replacement work. Include subprocesses and detached/remote executors holding write access. The host composition must provide process-tree containment or equivalent enforceable write revocation; if unsupported, keep the workspace quarantined and return HUMAN_ACTION_REQUIRED with WRITER_QUIESCENCE_UNPROVEN. Quarantine is durable, checked on every admission for that physical workspace, and cannot be cleared by lock release, TTL, restart or project renaming. A bounded quiescence deadline never authorizes continuing with an unproven writer.
- [ ] **Quiescence regression:** A prompt times out but attempts a late write; no new writer or certifying read is dispatched until write authority is demonstrably revoked.
- [ ] **Orphan regression:** Kill the host while a descendant retains write access. A replacement host may acquire the OS lock but must refuse workflow execution until containment/revocation is proven and reconciliation completes.
The Harness recovery policy is the authority for retries and reroutes. The pinned SDK must either have invisible automatic retries disabled for Harness operations or provide enough deterministic observability for every internal retry to be accounted for in the Harness attempt/recovery budget.
A single Harness attempt must not silently contain an unbounded or unaccounted SDK retry loop.
**SDK compatibility contract:**
Add a compatibility test/gate tied to the exact pinned `@opencode-ai/sdk@1.18.23` behavior relied upon by the adapter.
Changing the SDK version requires fresh compatibility evidence for:
- error classification signals;
- prompt/session lifecycle;
- cancellation/deadline behavior;
- retry behavior;
- malformed-response behavior.
Do not combine the failure-taxonomy hardening with an SDK version upgrade.
**Cleanup rule:**
Cleanup/session-abort/server-close failures are recorded as secondary operational facts. They do not replace the primary attempt failure that caused recovery.
