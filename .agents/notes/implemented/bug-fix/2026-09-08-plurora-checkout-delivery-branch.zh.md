# Agent Note: Plurora 交付绑定检出的分支

Status: implemented

[English](2026-09-08-plurora-checkout-delivery-branch.md) | 中文

## 问题

OpenCode 工作流提供自动生成的目标 id，而操作员选择检出的分支。从该 id 派生交付分支，会使已成功完成实现和验证的工作流在交付阶段失败：没有任何操作会创建或检出派生的分支。

## 决策

[宿主](../../../../apps/plurora-harness-host/src/main.ts)在打开持久化会话前，通过受管理的 Git 子进程读取项目检出的分支。它将该确切名称传给[交付描述](../../../../apps/plurora-harness-host/src/workflow-handlers.ts)，不依赖目标 id 或模型响应。PR（Pull Request）的基准分支来自部署配置中的受保护分支。

交付保留现有检查，核对当前检出的分支，并在暂存或提交前拒绝受保护分支和分离的 HEAD。宿主会话期间切换分支后，必须启动新宿主会话；宿主不会跟随切换，也不会重命名分支。

## 考虑过的替代方案

**重命名工作区以匹配每个目标。** 这会改变操作员选择的分支，并使工作区归属依赖自动生成的 id。

**在交付时读取当前分支。** 这会接受期间发生的分支切换，并在宿主启动时未绑定的分支上发布工作。

**让 OpenCode 选择交付引用。** 分支身份由宿主检出目录中的 Git 确定；模型提供的名称不能确立该身份。

## 影响

操作员自定名称的功能分支可以完成交付。宿主启动要求 Git 报告检出的分支；失败时不留下持久化会话。受保护分支和分离的 HEAD 仍可承载只读工作，但不能交付。

[无需密钥的宿主场景](../../../../apps/plurora-harness-host/tests/delivery-branch.snapshot.ts)使用已记录的提供方结果和模拟的 GitHub 响应，运行实现、验证和交付。Git 分支检查、提交和向临时本地远程仓库的推送均为真实操作。它还证明：切换分支后、处于受保护分支或分离 HEAD 时，交付会拒绝，且不会提交或暂存。该场景不提供真实 GitHub 认证或提供方运行证据。
